# 会话数据改造工作清单

## PC 端

- [ ] W01 `message.list` 只按会话 ID 一次查出该会话全部消息，不再分批返回。
- [ ] W02 数据库查询时就排好消息位置：早发生的在前，刚发生的在后；手机端不再处理消息先后。
- [ ] W03 手机进入会话时，桌面端在内存 Map 中记录“会话 ID → 正在该会话中的手机 WebSocket 连接”。
- [ ] W04 手机退出会话、断开连接时，桌面端立即移除对应的 WebSocket 连接。
- [ ] W05 新消息或消息更新时，只向正在该会话中的手机连接推送这一条消息。
- [ ] W06 停用每 650 毫秒查询并推送“会话信息 + 最新 100 条消息”的整段快照逻辑，保留原代码注释记录。

## 手机版

- [ ] W07 打开会话时只调用一次 `message.list(thread_id)`，接收全部消息并直接显示。
- [ ] W08 删除消息分页、补取、二次排序、UUID 排序的实际逻辑，保留原代码注释记录。
- [ ] W09 会话内容显示完成后，页面直接停在最下面。
- [ ] W10 收到实时消息时：已有同一条消息则原地更新；新消息直接加到最下面。
- [ ] W11 用户正在最下面时，页面跟随新消息；用户正在查看前面内容时，页面不跳动。
- [ ] W12 用户不在最下面且收到新消息时，底部中间显示圆形向下箭头；点击后回到最下面并隐藏提示。
- [ ] W13 进入会话时订阅，退出会话时取消订阅；首页、项目页和其他会话不接收当前会话的实时消息。
