# src-tauri 后端架构红线与调用链

本文件是 `src-tauri` 后端开发、排错、重构和代码审查的强制规则。

## 一、核心调用链

以下调用链是本项目必须保持的固定架构，任何业务功能都不得改变调用方向：

```text
业务调用方
    ↓
CliToolFactory 工厂获取当前 CLI 的业务实现类
    ↓
CliTool 统一接口
    ↓
当前 CLI 实现类
    ↓
CLI 生命周期获取 CLI 句柄
    ↓
本机 CLI，或 SSH 项目中的远端 CLI
```

SSH 项目中的完整链路是：

```text
业务调用方
    ↓
CliToolFactory
    ↓
CliTool 统一接口
    ↓
CLI 实现类
    ↓
CLI 生命周期
    ↓
SSH 隧道生命周期创建或取得 SSH 隧道
    ↓
CLI 生命周期在 SSH 隧道上创建、启动并取得远端 CLI
    ↓
CLI 实现类使用 CLI 句柄执行 CLI 业务
```

核心规则必须按以下含义理解和执行：

- CLI 生命周期调用 SSH 隧道生命周期，取得底层隧道能力，并由 CLI 生命周期在隧道上创建、启动和取得远端 CLI；
- 实现类调用 CLI 生命周期，获取 CLI 句柄；
- 接口定义 CLI 业务；CLI 实现类实现 CLI 接口；
- 业务调用只能通过工厂获取对应 CLI 业务实现类，再调用接口中定义的业务函数。

## 二、三项生命周期与业务边界

### 2.1 SSH 隧道生命周期

SSH 隧道生命周期只负责网络通道：

- 建立、复用、保活、恢复和关闭 SSH 连接及端口转发；
- 管理隧道、本地端口和远端端口；
- 向 CLI 生命周期提供创建和连接远端 CLI 所需的底层能力。

SSH 隧道生命周期不得：

- 依赖 `CliTool`、CLI 工厂或具体 CLI 实现；
- 解析会话、消息、模型、MCP 或其他 CLI 业务；
- 保存 CLI 客户端句柄；
- 成为业务调用方获取 CLI 的入口；
- 被业务调用方或 CLI 实现类直接启动、停止、释放或管理。

### 2.2 CLI 生命周期

CLI 生命周期负责 CLI 进程或服务的创建、就绪、复用、失效和终止：

- 本机项目由本机 CLI 生命周期管理本机 CLI；
- SSH 项目由 SSH CLI 生命周期调用 SSH 隧道生命周期，在隧道上创建和管理远端 CLI；
- 根据既定生命周期状态返回已经就绪的 CLI 句柄；
- 处理并发创建、复用、失效、终止和应用退出顺序。

CLI 生命周期不得：

- 管理会话、消息、模型、权限、MCP、扩展等业务；
- 实现某个 CLI 的业务协议；
- 把 CLI 句柄或隧道句柄交给业务调用方；
- 允许业务通过临时路径自行启动、停止或释放 CLI；
- 被会话业务、消息业务或具体工具绕过。

### 2.3 CLI 接口、实现类、工厂和业务调用

- `CliTool` 统一接口只定义稳定的 CLI 业务能力、统一输入和统一输出；
- `CodexCli`、`OpenCodeCli`、`ClaudeCodeCli` 等实现类分别实现统一接口；
- 各 CLI 的协议、数据读取、转换、错误处理和本机/SSH差异只能留在对应实现类及其专属客户端中；
- `CliToolFactory` 只负责根据当前 CLI 标识创建或取得对应的接口实现；
- 业务调用方只能持有统一接口类型，通过工厂取得实现后调用接口业务函数；
- 业务调用方不得直接实例化具体 CLI 实现类；
- 业务调用方不得直接调用 CLI 生命周期、SSH 隧道生命周期、CLI 句柄、OpenCode/Codex/Claude 内部函数或具体协议；
- 业务调用方不得通过新增调用路径间接触发、改变或绕过 SSH 隧道生命周期和 CLI 生命周期；
- 一个 CLI 失败时必须返回该 CLI 的明确错误，不得回退到其他 CLI、本机目录或其他 workspace。

固定关系如下：

```text
接口定义业务
→ 实现类实现接口
→ 实现类从 CLI 生命周期获取句柄
→ 工厂提供对应实现类
→ 业务通过工厂和接口调用业务
```

## 三、禁止反向调用

以下调用方向一律禁止：

```text
业务 → SSH 隧道生命周期
业务 → CLI 生命周期
业务 → CLI 句柄
业务 → 具体 CLI 内部函数
业务 → 具体 CLI 实现类的绕过接口调用

SSH 隧道生命周期 → CLI 接口、工厂或业务
CLI 生命周期 → 会话、消息、模型或 MCP 业务
公共接口/工厂 → 某个 CLI 的专属业务实现
```

新增或修改任何功能时，必须先确认：

1. 业务是否只调用了工厂和统一接口；
2. CLI 实现类是否只通过 CLI 生命周期获取句柄；
3. SSH 项目是否只由 CLI 生命周期调用 SSH 隧道生命周期；
4. 是否改变了隧道、CLI、接口、实现类、工厂或业务调用的职责；
5. 是否因为新增业务路径造成生命周期被重复创建、停止、释放或绕过。

任一项无法确认，必须停止编码并先报告，不得自行选择替代调用路径。

## 五、引用校验脚本

每次修改或新增 `src-tauri` 后端代码后，必须先执行：

```bash
pnpm check:tauri-architecture
```

脚本非零退出即表示本次修改不合格，不得提交。脚本只校验 import、模块限定引用和固定调用方向，不检查具体业务逻辑、业务算法或业务结果。

固定核心调用链必须保持以下语义：

```text
CLI 生命周期调用 SSH 隧道生命周期来创建 CLI
实现类调用 CLI 生命周期获取 CLI 句柄
接口定义 CLI 业务，CLI 实现类实现接口
业务调用通过工厂获取对应 CLI 业务实现类，再调用函数
```

业务→工厂→接口→实现类→CLI 生命周期→（SSH 时）SSH 隧道生命周期的方向不得反转，具体边界如下：

- 实现类不得直接碰 Tunnel；
- 业务不得直接碰 CLI 生命周期或 SSH 隧道生命周期；
- 接口不得依赖具体实现类；
- 工厂不得依赖 CLI 生命周期或 SSH 隧道生命周期。

每次修改或新增 `src-tauri` 下任意代码文件后，必须执行 `pnpm check:tauri-architecture`。校验脚本会递归扫描整个 `src-tauri` 代码树，跳过编译产物、依赖、文档、图片、压缩包和二进制，仅检查引用关系与调用方向，不检查业务算法或具体结果。

脚本非零退出时，不得继续编译、签名、发布或提交；所有编译和发布脚本都必须在仓库根目录确定后，把架构校验作为第一条可执行命令。REF-08 规定的 OpenCode Engine 生命周期引用也必须全量报告，不得因为是历史代码而加入白名单或豁免。

业务→工厂→接口→实现类→CLI 生命周期→（SSH 时）SSH 隧道生命周期的核心调用链必须保持不变；本规则同时遵守以上既有设计文档链接和用户确定的调用方向。

## 六、测试代码位置

- 所有独立测试脚本和测试源文件（包括 Rust 集成测试、测试夹具以及以后从生产源码拆出的测试文件）统一放在 `src-tauri/tests/`。
- 生产源码中不得新增独立测试脚本文件；生产源码只允许保留必要的 `#[cfg(test)]` 模块声明或测试入口，不放置测试实现。
- `src-tauri/tests/` 中的代码属于测试层，不得借助测试代码改变生产调用链；生产代码仍必须遵守业务→工厂→CliTool→实现类→CLI 生命周期→SSH Tunnel 生命周期。
- 测试执行使用 Cargo 的 test 机制，不把测试文件混入正式运行代码。
- 本次已将 factory 和 local lifecycle 两组测试迁入 `src-tauri/tests/unit/`；生产源码只保留测试模块声明/入口，不放测试实现。
